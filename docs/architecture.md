# 数据结构与模块

第一版是本地 Node.js 服务：HTTP 界面 + SQLite 数据库 + Playwright 浏览器执行器。浏览器执行器按平台账号隔离本地会话。默认只监听 127.0.0.1，支持一台电脑上的管理员与成员账号；服务器部署是后续阶段。

| 表 | 用途 |
|---|---|
| users / sessions | 管理员、成员和登录会话 |
| brands | 品牌及产品资料 |
| questions | 保存到问题池的原始问题，区分品牌认知和产品推荐 |
| tasks | 监测计划、问题组、定期执行账号及每日或每周执行时间 |
| runs | 一次任务执行及进度 |
| results | 每次运行中，每个“问题 × 账号”的最终采集结果及证据 |
| platform_accounts | 平台账号标签及其独立浏览器资料标识，不保存平台密码 |
| result_attempts | 每次尝试的状态、错误、截图与恢复信息；重试不会覆盖旧尝试 |
| submission_checkpoints | 发送前持久保存提交状态及原对话地址，按批次、问题和账号隔离；成功结果保存后清除 |

~~~~text
public/app.js ──HTTP──> src/server.js ──> SQLite
                            │
                            ├── src/questions.js（模板出题）
                            ├── src/core.js（批量任务与失败隔离）
                            ├── src/browser.js（网页操作）
                            └── src/analysis.js（指标与粗判）
~~~~

平台适配器需要完成：打开网页、新建对话、找到输入框、发送、等回答结束、提取回答和可见链接、截图。不同平台的页面定位规则集中在 src/browser.js，其余模块不依赖具体网页结构。

系统按“问题 × 账号”生成工作项，同一账号串行，不同账号最多并行两个；每条结果保存账号编号与运行时标签。既有任务迁移后使用原平台的默认账号，原有 profiles/<平台> 会话不移动。失败与成功分别保存，统计分母只使用成功采集的回答。网页端结果不会与模型 API 结果混合。

手动任务可以不绑定账号，运行时选择问题和账号，记录到 runs 的任务快照。定期任务保留自动执行账号。品牌快照保护历史报告的识别依据，账号改名不修改旧结果标签。

验证、登录暂停和回答超时后优先补采原对话；重启后使用保存的同平台历史对话地址，并核对原问题。无法确认时停止，不盲目发送。平台 B 的正文引用与搜索结果分别保存；网页改版仍需维护定位规则。

发送按钮点击或 Enter 前先将提交检查点写入本地数据库，等待回答时更新对话地址。即使进程突然退出，后续继续或重试也优先使用该检查点。若中断发生在新对话地址保存之前，可能无法恢复，但不会因为缺少结果而自动重新发送。旧版本已中断且未保存检查点的运行无法追溯补全提交状态。

每个监测问题应对应新对话中的一次问答。恢复时只接受唯一原问题及其后的一条回答；出现重复原问题、多条回答或回答后未分类的文字（可能是未回答的追问）时停止。平台新增界面文字也可能触发保守停止，需要人工核对和维护定位规则。暂停期间请勿在原对话追加问题。

定时任务按本机时区计算，每 30 秒检查一次到期任务；同一任务运行中不会再次启动。电脑休眠或程序退出时不会采集，重启后到期任务将执行。

## 可扩展方向

- 平台适配器可拆为独立文件，并加入页面版本探测与诊断。
- 增加人工复核状态，修正情感、品牌提及和引用判定。
- 报告可增加同题多轮稳定性、竞品占位和前后对比。
- 服务迁移到服务器时，浏览器执行器和 Web 服务可拆成独立进程，以任务队列连接。

监测使用有窗口浏览器。Windows 下启动时先最小化，再以不激活方式显示并放在其他窗口后方；自动问答、重试和人工处理提示不主动切换前台。只有主动点击“打开登录窗口”会激活窗口。窗口控制由 `src/window-control.js` 和 `scripts/browser-window.ps1` 实现，仅控制当前账号的浏览器进程；Windows + Edge 为验证基线。其他系统没有相同的窗口控制保证。登录入口、手机号/验证码输入及验证提示优先识别为待人工处理，结束当前等待并保存状态，人工完成后点击继续，没有人工处理倒计时。仍未恢复的网站访问或地区限制会另行提示。
