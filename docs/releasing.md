# 如何发布这个项目

## 发布目录

使用白名单导出的公开目录。里面应直接看到 README.md、src、public、docs、test 和 package.json。不要上传正在使用的本机工作目录。

公开目录不包含 .git 历史。首次发布前确认自己的 GitHub 账号和公开提交身份：提交中记录的是配置的作者姓名与邮箱，不一定是真实姓名。可使用自己选择的公开署名和 GitHub 提供的 noreply 邮箱。

## 网页上传

以下建仓库步骤仅用于首次发布。已有仓库请按下方“更新已有仓库”操作。

1. 在自己的 GitHub 账号创建 Public 仓库，名称建议 geo-web-monitor。
2. 上传公开目录中的内容，而不是把整个目录再套一层。没有上传的隐藏配置文件，可改用 Git 提交。
3. 检查首页图文、教程链接、LICENSE 以及 Actions 是否正常。
4. 设置简介和 topics，可参考 docs/sharing.md。
5. 如需固定可下载版本，再创建标签或 Release，写明实际版本范围与已知限制。

网页上传不一定包含以点开头的配置目录。若 .github、.gitignore、.gitattributes、.editorconfig 缺失，须补齐。

## 首次用 Git 上传

以下命令仅用于尚未建仓库的干净公开目录。先设置自己确认过的公开提交身份，再操作；已有仓库不要执行 git init：

```sh
git init
git add .
git diff --cached --stat
git commit -m "Initial public release"
git branch -M main
```

接着使用 GitHub 新仓库页面提供的 remote 和 push 命令。本文不提供虚构仓库 URL，也不自动使用本机已有的 Git 提交身份。

## 更新已有仓库

在原仓库的正常 Git 检出目录中更新经过审查的公开文件，用新的提交保留旧版本。不要重新初始化已有仓库，不要强制推送或覆盖历史。先拉取最新提交，比较本地公开清单与仓库文件；清单没有的文件需逐项确认是否过时，不要自动删除他人新增的文件。

提交前查看差异，确认只包含代码、文档、虚构示例及演示素材，没有数据库、账号资料、日志和私有工作记录。旧版本仍可通过提交历史查看；需要固定版本时再创建标签或 Release。更新代码不自动意味着发布了新 Release，也不需要每次创建新仓库。

## 发布前检查

- 记录实际完成的安装、环境和测试检查；未完成的新电脑或真实账号验收明确列出。
- README 截图只含虚构资料，真实运行目录不在提交中。
- 公开署名、邮箱和仓库 URL 都已确认。
- 推送后检查 Actions 结果；本地通过不能预先当作线上通过。
- 正式发布时更新 CHANGELOG 版本/日期；对外分享填入实际仓库链接。

本项目包含 npm run export:public 与 npm run check:public。后者接受一个已导出目录路径，检查清单、排除路径及本地 Markdown 链接；它不能保证识别所有秘密，仍需人工检查。
