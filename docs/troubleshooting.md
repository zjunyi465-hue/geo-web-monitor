# 排错指南

| 现象 | 检查与处理 |
| --- | --- |
| 网页无法访问 | 启动终端是否还在运行，端口是否正确；从项目目录重新启动 |
| 找不到 node:sqlite | 安装 Node.js 24+ |
| 找不到 Playwright / Edge | 安装依赖和 Edge，运行 npm run doctor |
| 端口占用 | 停止旧实例或设置 GEO_PORT，不重复启动共享数据的实例 |
| 输入框不出现 | 检查加载、登录、区域提示和网页改版，查看原窗口及截图 |
| 验证或登录暂停 | 任务暂停，不设人工处理倒计时；从任务栏打开原窗口处理，再点继续，不切换到其他对话 |
| 保存过登录却又要求登录 | 核对是否仍用同一个 Windows 用户、项目和浏览器资料目录启动；也可能是平台凭证失效。不要清空资料作为第一步排查 |
| 网页回答了但采集失败 | 查看执行记录阶段、完成条件与截图，尝试原对话补采 |
| 无法恢复原对话 | 检查历史地址、问题是否匹配；不要把新回答当旧样本 |
| 定期任务没跑 | 检查服务、开机/休眠、计划开关及本机时区 |
| 引用数不一致 | 分开核对正文引用、搜索结果和来源面板 |

失败不等于品牌未提及，也不等于平台封号。按执行历史定位导航、输入、提交、验证、回答等待、来源或截图阶段。

账号心跳失败可能与成功问答同时存在，只作为诊断。回答等待上限仍为 120 秒，长回答需人工核对完整性。

成功记录中的 `ERR_NAME_NOT_RESOLVED` 表示某个请求域名解析失败；`/site-icons/` 请求失败涉及来源网站图标，不证明来源网页无法访问。请求诊断不单独决定采集是否成功，系统也没有逐个打开引用网页验证可访问性。

定位规则在 `src/browser.js`，两个主流中文 AI 网页版的正文与来源处理分开实现。先运行隔离模拟网页测试，再用自己的账号单题对照。页面变化可能要求更新定位。

进程中断后，发送检查点用于防止重复提问。若原对话地址尚未保存，或原页面已有追加问答、无法唯一对应原问题与回答，系统会以 `RESUME_CONTEXT_LOST` 停止补采。请人工查看原对话，确认后再决定是否新建运行；不要把追加追问的回答当作原问题样本。
