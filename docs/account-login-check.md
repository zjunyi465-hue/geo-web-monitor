# 本地账号登录检查

账号池新增“检查登录状态”。使用账号已有的独立浏览器资料，在临时标签页打开平台首页，不填写、发送问题，不读取 Cookie 值作为登录有效的证明。检查结束关闭临时标签页，原问答标签页保留。

登录检查与“最近采集状态”分开保存。状态为：尚未检查、最近检查登录有效、需要登录、需要人工验证、暂时无法确认。页面展示检查时间、判断依据；未确认或需要处理时尽量保存截图，截图只在登录本地系统后可查看。

只有可靠账号标识和可用输入框同时出现，才认定检查时有效。平台出现登录表单、验证或地区限制时优先处理。游客输入框、隐藏登录控件、网络失败或找不到输入框都不能证明账号已登录或失效。平台页面更新、昵称账号缺少可识别标识时，可能返回“暂时无法确认”，请打开专用窗口人工查看；真实网站识别规则仍需使用者复测。检查不保证能发出问题，也不保证登录长期有效。

页面初始化后最多持续检查60秒，明确状态需要稳定至少1.5秒；导航最多等待20秒，即使导航超时仍继续识别已经打开的页面。输入框须可编辑且未标记正在加载。其中一个适配平台的默认“用户＋数字”昵称仅在左下角账号控件区域识别，正文中同样的文字不作为登录证据。等待上限耗尽时显示“检查等待达到上限”，不会直接判登录失效。检查返回elapsedMs记录页面识别等待耗时；它不含浏览器启动和导航耗时。

正在监测、等待人工处理、正在打开登录窗口或进行另一检查的账号不允许并发检查。检查不会自动处理验证码或登录。监测过程中发现登录或验证要求会更新对应状态，其他错误保持原有说明及截图。

数据库新增可空 login_check_json 字段；保留账号 ID、名称、浏览器资料和任务记录。检查截图位于私有 results/account-checks，不能加入公开包。

验证使用临时数据库、本地模拟页面和独立 Edge 资料，覆盖游客输入框、身份标识、登录入口、人工验证、地区页、隐藏登录控件、账号互斥、暂停任务保护以及界面按钮。未发送真实平台问题。这些模拟测试不保证实际网站各账号长期有效。
