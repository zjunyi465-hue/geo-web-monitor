# 隐私与公开分享

| 位置 | 内容 | 是否公开 |
| --- | --- | --- |
| data/ | 用户、品牌、问题、任务、结果、系统登录会话 | 否 |
| profiles/ | Cookie、本地存储和浏览器资料，可能包含登录凭证 | 否 |
| results/ | 原回答、截图和错误证据 | 否 |
| backups/ | 数据库与截图副本 | 否 |
| *.log / work/ | 运行日志、检查记录和临时文件 | 不加入公开包 |
| docs/assets/ | 隔离脚本生成的虚构演示截图 | 是 |

不保存平台密码，不代表浏览器资料不敏感。复制 profiles 可能复制登录权限。账号标签和备注也可能泄露个人资料。

## 发布包

`npm run export:public` 按白名单导出到 release-preview，排除 .git 历史、数据库、浏览器资料、结果、备份、日志与私有检查记录。首次发布可以使用干净包新建仓库；后续在同一个仓库提交更新，保留原有 Git 历史。不上传整个工作目录。

公开包把平台选择标签改为平台 A / B，只改变显示名称，不改变接入网址、技术标识或采集逻辑。源码能辨认目标平台，这不属于技术匿名化。使用者自己的采集结果、诊断和原网页可能显示实际平台名称；这些数据不进入公开包。

`.gitignore` 不会清除已经提交的文件或 Git 历史。公开前还需要检查待上传文件、截图、Git 作者姓名及邮箱。演示截图必须用虚构数据，不用真实截图打码代替。

## 提交问题

公开 issue 只提交平台、步骤、预期、实际行为与脱敏错误。检查截图中的手机号、头像、客户信息、标签页、路径和 URL 参数。不要提交 Cookie、认证头、验证码、密码、数据库或完整私有回答。

## 部署边界

默认监听 127.0.0.1，团队成员共用项目数据。本版不提供成员项目隔离、HTTPS、服务器任务守护和公网上线保证。

机构核对名称、合并关系和备注保存在本地数据库中，可能包含客户或业务信息；它们与信源标注、任务专题和实际回答一样不进入公开导出。团队成员按当前共享规则可见，公开 issue 不要附带这些私有记录。
