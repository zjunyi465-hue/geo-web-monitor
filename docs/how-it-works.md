# 用最容易理解的方式解释这个项目

## 为什么不用模型 API 代替网页监测？

支持联网搜索的模型 API 可以返回带来源的回答，但这测量的是某组 API 设置下的输出。GEO 监测要回答的是：“普通用户在某个 AI 网页产品里输入这个问题，页面实际展示了什么？”两种数据来源各有用途，不能直接等同。

## 网页采集的六步

1. 添加品牌资料和问题。问题可手动输入，也可按品牌资料与规则模板生成。
2. 团队核对问题；保留原文，区分“问题含品牌名”的认知题和“问题不含品牌名”的推荐题。
3. 用户选择平台账号与执行方式。系统将每个“问题 × 账号”拆成独立工作项；不同账号的登录状态分别保存。
4. Playwright 打开真实网页。每个问题新建对话，输入原问题并发送。
5. 程序等待回答正文稳定，读取页面可见文字和来源链接，保存截图。平台 A 会展开当前回答的参考资料列表，再提取其中的来源。
6. 分析程序对成功回答统计提及率、来源域名和情感关键词；失败项单独显示。

## 怎样判断采集是可信的？

先只测一个问题，核对该次原对话、截图、保存的回答原文和引用链接，确认一致后才批量运行。系统保存时间、平台、账号标签和问题原文；发送前尝试记录搜索、思考和页面模型/模式标签；控件未暴露可靠状态时记未知，不自动切换设置。页面状态不证明实际执行过搜索或后端模型版本。同题重复监测，才能观察变化。

网页可能出现访问限制、要求重新登录或改版。登录或验证会进入待人工处理状态；无法访问或采集时报告失败，并尽可能保存截图。没有取得可用回答时，不默认判定品牌未出现。

## 自动出题是怎样做的？

第一版使用**结构化资料 + 问题模板 + 去重 + 人工审核**。例如填入“品牌：星河”“类别：数据分析工具”，系统会生成“星河是什么？”和“有哪些值得考虑的数据分析工具？”两类问题。这个办法可解释、没有模型调用费用，但提问多样性有限。后续可接本地运行的语言模型生成更多自然问法，仍由人审核后入库。

监测使用有窗口浏览器。Windows 下启动时先最小化，再以不激活方式显示并放在其他窗口后方；自动问答、重试和人工处理提示不主动切换前台。只有主动点击“打开登录窗口”会激活窗口。窗口控制由 `src/window-control.js` 和 `scripts/browser-window.ps1` 实现，仅控制当前账号的浏览器进程；Windows + Edge 为验证基线。其他系统没有相同的窗口控制保证。登录入口、手机号/验证码输入及验证提示优先识别为待人工处理，结束当前等待并保存状态，人工完成后点击继续，没有人工处理倒计时。仍未恢复的网站访问或地区限制会另行提示。
