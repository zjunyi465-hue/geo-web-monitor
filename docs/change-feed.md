# 变化动态

这个页面回答的是：同一任务中，相邻两次保存的回答在品牌/对标名称出现和来源集合上，发生了哪些变化。它不检测全文的所有措辞改动，不自动解释变化原因。

## 查看流程

选择品牌，点击“应用筛选”。记录按本次运行时间从新到旧排列，每页20条，列表内部滚动。卡片显示问题、平台/账号、两次采集时间及差异；展开“查看前后回答”核对正文和保存来源。

默认查看全部变化记录，可改为仅条件已确认或仅条件未完整记录。“更多筛选”提供任务、平台、账号、当前专题、变化类型、跟进状态和日期。折叠不会取消已应用条件；“清空筛选”恢复当前品牌的全部记录并回到第一页。修改表单后需点击应用，结果才按新条件更新。

日期筛选使用本次运行开始日（北京时间），基线仍是同任务的直接前一次结束运行，可位于日期范围外。专题按当前成员筛选，不能当作过去专题成员的快照。

## 两类记录

共同要求：同任务相邻两次已结束运行、同一问题/平台/账号，各自只有一条成功且非空的最终回答；问题和账号在任务快照内，问题文字与类型一致，品牌识别资料（名称、别名、官网）一致。失败、缺失、重复归属或快照不足不能用于判断品牌消失，也不能跳过后改用更早的成功回答。

| 标签 | 判断与用途 |
| --- | --- |
| 条件已确认一致 | 两次采集前后记录的联网、思考、模型/模式值均明确且一致，可查看同条件差异、连续次数及团队跟进 |
| 条件未完整记录 | 至少一个条件未知，且四个采集时点之间没有已知值冲突；仅供原文对照，不进入同条件趋势、连续次数或跟进 |

这里的“确认”仅针对保存的页面设置值，不证明实际搜索过程或后端模型版本。两类记录可以放在同一列表，但总条数只是符合筛选的变化记录数，不是提及率或优化效果。

## 变化如何计算

我方和“关注对标”的名称只匹配回答正文，标题不计正文出现。一次回答即使多次出现名称，也只判断出现/未出现。当前人工确认的对标名单同时用于两次原文；名单改变会重新计算，受影响的跟进标记不自动沿用。

正文引用和搜索来源分别按保存的原始URL集合比较。卡片显示“仅本次保存”“仅前次保存”，不表示网页新增、下线或平台不再引用。正文引用只有两次保存数量均与页面报告数量核对一致时，详情才说明该完整性检查；数量一致仍不证明内容正确。搜索来源没有完整数量保证。

连续次数仅适用于条件已确认的同问题/平台/账号记录，遇失败、缺失、归属不唯一或条件无法确认时停止。单次变化、连续出现和来源增加都不能证明某项内容优化有效。

## 跟进与空结果

条件已确认的记录可以标记未查看、已查看或持续关注，团队共享最后标记人和时间。不修改原回答或报告统计，不保存全部标记历史。保存时检查原文版本、对标名单和最后更新时间；冲突时先刷新。原文或名单变化产生的新记录不会套用旧跟进。

选择跟进状态会隐藏没有该状态的条件未确认对照。空结果分为没有可配对回答、配对中没有所列变化、已有变化被进一步筛选排除；页面底部的“比较规则与未纳入原因”可查看具体情况。没有名称/来源变化不表示全文相同或品牌表现稳定。

来源仅允许可用格式的无凭证HTTP(S)链接，原文作为文字显示，不执行其中HTML。标记随数据库备份，删除相关结果会清理对应标记；真实数据不随公开包分发。
